# Kun 系统架构文档

## 一、项目概览

| 属性 | 值 |
|------|-----|
| 仓库 | `https://github.com/KunAgent/Kun` |
| 包名 | `kun-gui` |
| 产品名 | `Kun` |
| 许可证 | PolyForm-Noncommercial-1.0.0 |
| 定位 | 面向开发者的需求优先编程（Specification-Driven Development）桌面工作台 |

Kun 是一个基于 Electron 的桌面 AI Agent 工作台。它的核心设计理念是"需求优先编码"——用户先用自然语言描述需求（SDD），AI Agent 据此制定执行计划，然后逐步实现。

│  Main (Electron 34)                      │
│  - 窗口/托盘/菜单管理                     │
│  - Kun 运行时进程管理（启动/健康监控/重启） │

│  Kun Runtime (独立进程)                   │
│  本地 HTTP/SSE Agent 运行时               │
│  - 手写 HTTP 服务器 + Router              │
│  - Agent 循环引擎（AgentLoop）            │
│  - 工具系统（ToolHost + 多种 Provider）    │

关键技术决策：**单体运行时架构**。所有工作模式（代码聊天、Write 写作助手、日程任务、手机连接）共享同一个 `kun serve` 进程，不需要多个运行时协同。

## 四、功能模块详解

### 4.1 核心：Agent 对话循环

详细见 `02-AI-Agent底层实现机制.md`。核心类 `AgentLoop`（约 2400 行）负责：
- 接收用户消息，与 LLM 交互
- 工具调用分发（并行/串行）
- 上下文压缩、Token 经济
- 目标（Goal）自动恢复
- 审批流和生命周期 Hook

### 4.2 需求驱动开发（SDD）

用户描述需求 → Agent 制定计划 → 逐步执行 → 验证。SDD 子系统负责：
- 需求起草/编辑/历史管理
- 与计划面板联动
- 需求到实现的追溯

### 4.3 计划面板（Plan）

- Plan 模式的 Agent Turn 只暴露只读调查工具 + `create_plan` 工具
- 支持计划审批、修改、执行步骤追踪
- 与 Todo 系统联动

### 4.4 聊天工作区（Chat）

- 多话题（Thread）管理
- 流式消息展示（Markdown +代码高亮）
- 工具调用可视化（Diff 展示、文件操作预览）
- 审批交互（用户确认/拒绝工具调用）
- 中断/引导（Steering）

### 4.5 Write 写作工作区

- 文件树浏览器
- TipTap 富文本编辑器（Markdown 模式）
- 内联补全（Inline Completion）
- Markdown 资源管理
- 文档导出（HTML → DOCX）

### 4.6 集成终端

- xterm 6 + node-pty
- 与 Agent 共享工作区目录
- 支持 Web Links 插件

### 4.7 日程管理（Schedule）

- 定时任务配置和执行
- 基于 MCP 的调度系统
- 克隆（claw）兼容

### 4.8 模型管理

- 多供应商配置（OpenAI 兼容 / Anthropic Messages）
- 默认模型：DeepSeek V4 Pro
- 自动模型路由（根据上下文选择不同模型）
- 用量统计（Token 数、费用）

### 4.9 设置面板

提供完善的 GUI 设置管理：通用设置、模型配置、Skills 管理、Memory 管理、MCP 服务器管理、Hook 配置、代理设置等。

## 五、关键实现机制

### 5.1 Ports & Adapters 架构

所有核心能力通过抽象端口定义，具体实现由适配器提供：

```typescript
// 端口（位于 kun/src/ports/）
interface ModelClient { stream(request): AsyncIterable<ModelStreamChunk> }
interface ToolHost { listTools(context): Promise<ToolDef[]>; execute(call, context): Promise<Result> }
interface ThreadStore { create/update/delete/list... }
interface SessionStore { load/save... }
interface MemoryStore { create/update/delete/list/retrieve... }
```

### 5.2 单例 + 工厂模式

- 运行时工厂（`runtime-factory.ts`）一次性装配所有组件
- 所有 Store、ToolHost、ModelClient 均为模块级单例
- `AgentProvider`（GUI 侧）由 `registry.ts` 工厂创建并缓存

### 5.3 缓存优先（Cache-First）策略

- 系统提示词前缀是不可变的，可复用于多轮对话
- 利用 DeepSeek 的 Context Caching 特性，大幅降低首 Token 延迟
- 工具目录被标准化并缓存，仅在工具集变化时失效

### 5.4 追加写（Append-Only）事件日志

- Thread 的事件和消息以 JSONL 格式追加写入
- 渲染进程通过 SEQ 序列号回放事件
- SSE 用于实时流式传输

### 5.5 混合存储（Hybrid Storage）

- JSONL 作为权威记录（canonical）
- SQLite（better-sqlite3）作为可重建索引
- 启动时自动做增量同步（backfill）
- 元数据文件自动压缩（>1MB 时触发）

### 5.6 功能开关（Feature Flags）

所有扩展能力通过配置显式控制：

| 能力 | 配置键 |
|------|--------|
| MCP 集成 | `capabilities.mcp.enabled` |
| Web 搜索 | `capabilities.web.enabled` |
| Skills | `capabilities.skills.enabled` |
| 子 Agent | `capabilities.subagents.enabled` |
| Memory | `capabilities.memory.enabled` |
| 计算机控制 | `capabilities.computerUse.enabled` |

### 5.7 Hook 生命周期系统

外部脚本可在 Agent 生命周期关键节点介入：

```
PreToolUse -> PostToolUse
UserPromptSubmit -> TurnStart -> ... -> TurnEnd
PreCompact
```

Hook 可以：观察（observe-only）或拒绝/修改操作。

### 5.8 契约优先（Contract-First）的 IPC

- `src/shared/` 中的 Zod Schema 定义所有跨层契约
- Preload Bridge 严格类型化 `window.kunGui` API
- IPC 消息经 Zod 校验

### 5.9 审批策略

工具执行策略分为：

| 策略 | 行为 |
|------|------|
| `auto` | 自动执行 |
| `on-request` | 首次使用请求用户批准 |
| `suggest` | 建议确认但不强制 |
| `never` | 永远不执行 |
| `untrusted` | 始终需要批准 |

## 六、数据流

```
用户输入（Renderer Composer）
  → Zustand Store dispatch action
  → window.kunGui.sendMessage()（Preload Bridge）
  → IPC Handler（Main Process）
  → runtimeRequest() POST /v1/threads/{id}/turns
  → Kun HTTP Server
  → AgentLoop.runTurn()
  → CompatModelClient.stream() → DeepSeek API
  → 工具调用（bash, write, read, mcp 等）
  → SSE 事件流返回
  → runtime-sse-ipc.ts 中继到 Renderer
  → Zustand Store 更新 → React 重新渲染
```

## 七、与 Vico 架构对比

| 维度 | Kun | Vico |
|------|-----|------|
| 平台 | Electron 桌面应用 | Web 应用（Hono 后端 + React 前端） |
| Agent 框架 | 自研 AgentLoop | Vercel AI SDK（ai 包） |
| LLM 客户端 | 手写 CompatModelClient | 通过 AI SDK 抽象 |
| 数据库 | JSONL + SQLite 混合 | Drizzle ORM + better-sqlite3 |
| 认证 | Bearer Token | better-auth（Session Cookie） |
| 多租户 | 无（本地单用户） | 有（tenant_id 隔离） |
| 工具系统 | 自研 ToolHost + 多 Provider | AI SDK Tool 系统 |
| 记忆 | 文件 JSON + N-gram 匹配 | 向量嵌入 + 余弦相似度 + 混合搜索 |
| Skills | 文件扫描 skill.json/SKILL.md | 文件系统 manifest.json + tools.ts |
| 子 Agent | 内置 delegation 系统 | 无 |
| MCP | @modelcontextprotocol/sdk 完整集成 | 无 |
| 流式 | SSE（手写） | SSE（AI SDK streamText） |

    "model": "deepseek-v4-pro",

    "mcp": { "enabled": false },
