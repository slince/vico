AI Agent 产品标准知识库页面完整能力报告
报告总览
本文面向Mastra/AssistantUI 多智能体产品，分为两大核心板块：
UI 产品展示层完整能力（页面布局、模块、交互、权限、数据看板、Agent 关联管理）
AI 检索 / RAG 底层完整能力（文档解析、切片、混合检索、重排、溯源、指标体系、Token 用量统计、幻觉控制）
适配前端 assistant-ui + 后端 Mastra Agent 架构，覆盖个人 / 企业级双场景，可直接作为产品 PRD、设计规范、技术验收标准。

   二、UI 层核心完整能力清单
   （一）知识库生命周期管理
   创建知识库
   基础信息：名称、描述、封面、私有 / 团队 / 公开可见范围
   高级 RAG 参数预设（UI 可视化滑块配置，无需代码）
   切片分段长度、重叠值、相似度阈值、召回条数、重排开关
   未命中回答策略：自由回答 / 固定兜底文案 / 拒绝回答 / 跳转人工
   绑定 Agent 配置：多选关联智能体，设置该库是否为 Agent 默认知识库
   知识库编辑 / 归档 / 删除
   归档：隐藏但保留向量数据，可恢复；删除：彻底清空向量库 + 文档文件
   版本快照：支持保存当前知识库配置快照，一键回滚切片 / 检索参数
   多知识库隔离
   Agent 对话时可指定单 / 多知识库联合检索，前端对话面板支持切换检索库范围
   （二）文档导入与解析 UI 交互
   多渠道导入
   本地拖拽上传：PDF/Word/Excel/PPT/TXT/MD/ 图片（JPG/PNG 扫描件 OCR）
   在线 URL 抓取：网页、飞书 / 语雀 / Notion 文档链接自动解析
   批量压缩包上传、云端网盘文件导入
   手动在线编辑器：直接新建 Markdown 知识库文档（AI 润色 / 摘要生成）
   导入进度可视化
   实时进度条：文件上传 → 文本提取 → OCR 识别 → 智能切片 → 向量化入库
   异常弹窗：乱码文件、加密 PDF、超大文件、解析失败文档清单，支持单独重试
   文档在线编辑
   内置富文本 / Markdown 编辑器，修改后自动重新切片更新向量索引，无需重新上传
   （三）智能检索 UI 交互（知识库内检索 + Agent 对话检索联动）
   库内全文搜索：关键词 + 语义双模式，支持筛选文档类型、时间、标签
   检索结果高亮：命中片段标黄，展示相似度分值、来源文档、段落位置
   检索历史、热门搜索词推荐、无结果优化提示（补充关键词 / 新增相关文档）
   一键将检索内容推送至 Agent 对话窗口提问

   文档多标签管理：自动 AI 生成摘要、实体标签、手动自定义业务标签

   知识库全局标签库统一管理

   知识库级权限：单独设置成员 / 用户组访问权限
   文档级标签权限：敏感标签文档仅高管可见，检索底层过滤无权限向量

第二部分：AI 检索 / RAG 底层完整能力（Agent 调用知识库核心技术标准）
一、文档解析预处理能力
全格式解析引擎
文本类：TXT/MD/Word，自动识别标题层级、段落、列表
版式类：PDF（扫描件 OCR、表格提取、水印过滤、加密解密）、PPT
表格类：Excel/CSV，结构化存储，支持按列索引检索
图片类：JPG/PNG 扫描件 OCR，提取图表文字
清洗降噪
自动过滤页眉页脚、页码、广告、重复内容、空白段落、乱码字符
结构化输出
输出统一 Markdown 结构化文本，保留标题层级，用于智能分层切片
二、智能切片（Chunk）系统（UI 可视化配置）
多种分段策略可选：
固定长度分段：自定义 chunk 长度、重叠 overlap 值（0~200）
语义分段：基于句子语义边界切割，保证单 chunk 语义完整
标题层级分段：按 #/##/### 自动拆分，章节完整不割裂
FAQ 专属分段：一问一答独立 chunk
批量重切片：修改分段规则后一键全库重新向量化
单文档自定义分片：手动拆分 / 合并 chunk，单独调整向量
三、混合检索核心能力（Hybrid Search，Agent 问答底层）
1. 双检索引擎并行
   BM25 关键词检索：精准匹配型号、代码、工号、专有名词、数字，解决向量语义丢失精确匹配问题
   向量语义检索：文本向量化余弦相似度匹配，理解同义、转述、模糊提问
2. 可视化可调参数（前端滑块配置）
   语义相似度阈值：0~1，低于阈值直接过滤结果
   语义召回条数 Top-N（1~20）
   关键词召回条数 Top-M（1~20）
   混合权重分配：语义 / 关键词结果合并权重调节
3. Rerank 重排模型（高阶能力）
   检索后使用交叉编码器对混合结果二次打分重排序，大幅提升 MRR/NDCG 指标，UI 开关一键启用 / 关闭
   四、检索后处理与答案生成管控（解决 AI 幻觉）
   知识溯源强制引用
   Agent 回答自动挂载引用标记，每条结论绑定对应文档 + chunk 段落，前端对话可点击展开原文；
   配置开关：是否强制展示引用来源、无检索结果时禁止编造答案。
   未命中策略四模式
   自由发挥：允许大模型自有知识补充
   固定兜底文案：预设统一提示词
   拒绝回答：直接告知无相关知识
   转人工：推送人工工单
   幻觉抑制机制
   Prompt 内置校验规则：答案必须完全基于检索上下文，超出知识库内容需明确标注 “无相关资料”
   上下文压缩
   多 chunk 超长检索结果自动摘要压缩，控制输入 Token，降低成本、减少窗口溢出
   五、权限检索隔离底层逻辑（安全核心）
   检索前置过滤，而非事后屏蔽答案：
   每条向量 chunk 绑定标签权限元数据（部门、安全等级、用户组）
   Agent 发起检索时，携带当前用户权限标签，向量库仅返回匹配权限的片段
   越权拦截：无权限文档向量完全不参与检索，杜绝 “模糊提问泄露敏感数据” 风险
   六、Mastra Agent Token 用量全链路统计能力（对接原生 Metrics）
1. 三层维度自动采集 Token 消耗
   会话 Thread 维度：单条对话调用知识库产生的 input/output/total token，存入 Mastra Metrics DuckDB，前端 ThreadList 展示会话累计消耗
   知识库维度：单个知识库被所有 Agent 调用总 Token，UI 单库统计面板展示
   Agent 全局维度：单个智能体关联所有知识库的全量 Token 总消耗，后台大盘展示 Agent 消耗排行
2. 采集逻辑
   Agent 调用 RAG 检索时，RequestContext自动注入kbId、threadId、agentId标签；
   每轮模型调用自动上报inputTokens/outputTokens/totalTokens至 Mastra 内置 Metrics 存储，支持 SQL/SDK/Studio 三种查询方式。
3. 量化指标
   检索输入 Token：知识库 chunk 拼接上下文消耗
   生成输出 Token：基于知识回答输出文本消耗
   缓存读写 Token：向量检索缓存命中节省消耗单独统计
   七、检索质量量化指标体系（验收标准）
1. 检索召回精度指标
   表格
   指标	行业合格阈值	说明
   Recall@5 召回率	≥85%	相关知识全部检索出来比例
   Precision@5 精确率	≥80%	返回前 5 条内有效知识占比
   MRR@5	≥0.75	首个有效知识的排名倒数均值
   NDCG@5	≥0.85	结果排序综合质量
2. 生成回答质量指标
   Faithfulness 忠实度 ≥0.9：答案无编造，完全基于检索知识（抑制幻觉核心指标）
   Answer Relevance 回答相关性 ≥0.85：回答贴合用户提问
   Context Utilization 上下文利用率：检索 chunk 有效引用比例
3. 性能指标
   端到端检索响应延迟 <3s
   TTFT 首字输出延迟 <1s
   并发 QPS：企业级支持≥50 并发检索
   解析入库速度：单 100 页 PDF <10s
   八、扩展高阶检索能力
   多模态检索：图片 OCR 向量检索、表格结构化检索
   时间权重检索：优先返回近期更新文档，过滤过期知识
   知识库联合检索：Agent 一次提问同时调取多个知识库，按权重合并结果
   检索改写（Query Rewrite）
   LLM 自动扩写、拆分用户问题，补充同义关键词，提升低召回场景命中率（UI 开关控制）
   检索缓存：高频相同问题缓存向量结果，降低重复 Token 消耗
   第三部分：产品落地价值总结
   UI 层价值
   统一管理 Agent 配套知识资产，可视化 RAG 参数降低用户使用门槛，权限与审计满足企业合规；绑定 Mastra 智能体实现对话 - 知识库双向联动，用量看板实现成本可视化管控。
   AI 检索底层价值
   标准企业级混合 RAG 架构，完整切片、重排、溯源、幻觉抑制体系；深度对接 Mastra 原生 Metrics，实现会话 / 知识库 / Agent 三层 Token 用量自动统计，适配多智能体投研 / 客服 / 办公全场景。
   适配技术栈
   前端：assistant-ui Thread/ThreadList 对话组件、i18n 多语言、shadcn UI 管理页面
   后端：Mastra Agent、DuckDB 原生 Metrics 向量指标存储、RAG 检索管道、RequestContext 标签埋点统计 Token 消耗。
